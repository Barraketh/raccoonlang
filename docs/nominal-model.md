# Nominal family model

This construction supports the nominal principles and the conservative elementwise size rule in
[kernel.md](kernel.md#nominal-type-families). It models the stated calculus relative to ZFC with inaccessible
cardinals and an audited consistent trusted prelude. It is an informal mathematical construction, not a
machine-checked theorem about the implementation. In particular, fixed-width value hashes and the
implementation's coverage/refinement decisions require separate justification; neither is an axiom of this model.

## Universe representation

Work in ZFC with a strictly increasing countable sequence of strongly inaccessible cardinals kappa_n. Write V_n =
V_{kappa_n}; define the broad coded universe U_n = V_n x V_n. A data type is interpreted by an ordered pair (extension,
label), with El the first projection. This avoids inductive-recursive or circular definitions of a universe of only
recognized type codes. Arbitrary pairs may inhabit a universe; only interpretations of actual syntax must have the
designated labels. U_n is a set in V_{n+1}, although U_n is not in V_n. Every element of U_n is in V_n.

Use pairwise disjoint finite tags in labels:

* Type universe: (Type, n, normalized-kind, normalized-scope), extension U_n.
* Prop sort: a separate Prop tag with scope, extension the two truth values. It is data at Type_0; an individual
  proposition is a truth value, without a nominal family label.
* Type-valued Pi: (Pi, binder-group modes and count, closure kind, closure scope, mentioned scope, interpreted domain
  telescope, interpreted codomain family). Domain/codomain components are semantic values, not source identities.
* Type family instance F(a): (Family, declaration identity F, full semantic argument tuple a). Include phantom
  arguments, level/kind/lifetime parameters, and dependent proof arguments modulo proof irrelevance.
* Quot: a separate primitive label may be used, but no nominal principle is asserted for it or for arbitrary
  axiomatically supplied types.

The extension of a Type-valued Pi is its ordinary extensional dependent function set. A Prop-valued Pi is a truth value:
true iff all its instantiated codomains are true. Proofs have the one canonical semantic value *. Proof-valued
lambda/application are interpreted by proof erasure and result typing; they are not ordinary graph functions. Since Prop
is separate and noncumulative after Prop separation, proof-versus-data status is stable under substitution, so this
split interpretation is well defined. An alternative uniform interpretation uses Aczel trace encoding with true proof
value empty-set; do not mix an ordinary graph-function interpretation of all lambdas with singleton proof values.

For a Type-valued Pi at level n, each domain's extension is in V_n, and the codomain values are interpreted codes in
V_n. The domain has cardinality less than kappa_n, so regularity bounds the ranks of all components of the codomain
graph below kappa_n. Strong-limit closure bounds the dependent product. The label and extension are therefore both in
V_n. A Pi ending in a universe has its ordinary next-level classifier, so the universe's full extension is accommodated
there.

Data inductives are constructed by the bounded erased-carrier and simultaneous typed-rule construction below. Values are
constructor tags with semantic stored field tuples, or extensional function graphs; a value does not contain its
constructor head's type, the family's complete code, erased parameters, closure syntax or node identity. Semantic typing
is an external relation. Thus `Tree` values containing `List(Tree)` values do not contain the complete `Tree` extension
within their own transitive closure. A genuinely stored field that is itself a type value does contain that type's code,
but the ordinary field-size rule charges its classifier successor and places it in a strictly higher universe than the
code's own universe. Only after the fiber extensions have been constructed do we wrap them in nominal type labels.
Prop inductives are truth-valued least predicates generated by their constructor rules, erasing proof trees. Their
parameter/index domains may be larger sets. They have no nominal labels, injectivity or generativity. Small elimination
is proof erasure. Large elimination is valid for an empty exact fiber, or a declaration-certified singleton constructor
whose data fields are functions of the exact proposition's indices and parameters and whose remaining fields are proofs.
Its result depends on those indices/parameters, never on which proof tree was chosen. The implementation's recovery
metadata is singleton-only (`projectionInfo` exists only for a one-constructor declaration). The dependent witness
argument below explains the recovery-source certification. An Eq-elimination into data transports along semantic
equality by identity. Blocked operational equality transports are compatible with this denotation; a consistency model
need not prove operational completeness or canonicity.

## Elementwise rank lemma

Define Small_n(T) as: every value in the interpretation of T lies in V_n. The declaration check is a sufficient
syntactic condition for Small_n, not a test that the entire extension of T lies there.

1. T = Type_m and m <= n: each element of U_m is in V_m, hence V_n. At m=n the full U_n is not in V_n, but that is
   unnecessary.
2. T = Prop, or T is a proposition: truth values and singleton proof values lie in every V_n.
3. T = Pi(x:A).B: require A's classifier level <= n (or A a proposition/sort parameter admitted by the kernel), and
   recursively Small_n(B) for every admissible x. El(A) has cardinality < kappa_n. Each selected result has rank <
   kappa_n, so regularity makes the entire function graph an element of V_n. For multiple binders, apply the same
   telescope argument. A universe in domain position is charged by its classifier (succ m), not by m; this is why Type_0
   -> Type_0 fails at level zero.
4. Other typed T: its classifier level <= n gives El(T) in V_n, and transitivity yields every element in V_n.
5. Level/kind/lifetime parameters are kernel annotations, not object types; their valuations are natural levels and
   bounded finite normalized annotations, which fit every V_n. They must be exempt from TypeChecker.getUniverse, not
   mistaken for large data domains.

The lemma gives full argument tuples in V_n; their finite family labels therefore lie in V_n. N1 follows from
injectivity of ordered-tuple labels; N2 from declaration tags; N3 from disjoint Family/Pi/Type tags and injective Type
annotation labels. In N3, Pi means a Type-valued Pi; Prop-valued function propositions have no Pi label and are not data
types at the universe in which a Type family instance is compared.

## Interaction obligations

* Equality is semantic equality (including of the entire coded type), with proofs erased. Propositional extensionality
  equates propositions with equal truth value, without identifying data type labels. Function extensionality is
  compatible with labels containing semantic argument functions. Any semantic equality can transport through an indexed
  family; this permits quotient-equal indices and extensionally equal functions to have equal labels.
* Quot(A,r) uses the equivalence relation generated by r and equivalence classes in El(A), retaining rank bounds.
  `Quot.sound`, lift respecting r, and Prop-valued induction have their usual interpretation. Quot.mk is neither
  injective nor generative. An arbitrary axiom of type Type may denote any coded type, including Nat; never refute it by
  its symbolic name.
* Structure eta uses one-constructor tuple values at eligible nonrecursive zero-index data families. Tuple
  projections/reconstruction are inverse; proof fields are singleton entries. Eta does not erase the nominal label of
  the value's type.
* Conversion only needs to imply equality of semantic interpretations, not reflect all semantic equalities.
  Beta/match/native equations, lambda extensionality, proof irrelevance, struct eta and packed decoding preserve it.
  Family labels use semantic values rather than operational representatives, so equal functions, eta values, proofs and
  quotient classes get equal labels. Value keys are an implementation optimization and never enter semantic labels. The
  existing fixed-width-hash equality shortcut is a pre-existing implementation proof gap, explicitly outside this
  repair; key assertions are empirical validation and do not establish mathematical collision freedom.
* Kinds/scopes can share universe extensions while distinct universe annotation labels distinguish them. Erasing usage
  discipline is enough for consistency; this model does not by itself prove linear resource preservation or lifetime
  confinement. Lifetime variables are interpreted by valuations; unequal open normal forms may still coincide after
  substitution, so they do not provide apartness. Keep the existing T1–T5 trusted-prelude obligations and no
  lifetime/kind refutations.
* Sealing restricts eliminator access and does not alter denotation or nominal principles. Only the prelude's sealing
  obligation prevents abstract inhabitants; it is independent of logical consistency.
* A universe-polymorphic declaration denotes a metatheoretic family indexed by level valuations. Level quantification is
  Large and not an object of any U_n; its declarations are instantiated before ordinary use. The size inequalities must
  hold under every valuation (use normalized Level.leq, never choose values for rigid variables). No object-level
  universe of all levels is added.

## Explicit extension-smallness construction

Fix one environment and annotation valuation and one complete common parameter tuple p. The construction is pointwise at
p; neither the space of all parameters nor the space of all indices must lie in a low family's declared universe. A
larger ambient set universe contains the index domains and the finitely many grades used by this instantiated
declaration. Low Type extensions are bounded separately at their own grades, not by this ambient universe.

A proof-erased positive family need not be polynomial: a certified-positive family need not itself be a polynomial
functor after proof erasure. For `G(A:Type):Type | mk(h:Nonempty(A))`, the extension is empty iff A is empty and
otherwise singleton. Its bound is a constant singleton, and its membership condition is an independent existential
witness in A. The following construction distinguishes these two objects throughout. It uses ordinary containers only
for bounds on erased payloads. Actual extensions are selected by positive guards, and are never identified with the
initial algebra of an unguarded polynomial.

### A. Two invariants and their operations

Let Z be a fixed tuple of candidate data carriers and ambient index domains. A relation valuation rho specifies subsets
R_j(i) of the candidate data carriers and truth predicates Q_j(i) for recursive propositions. Order valuations by
componentwise inclusion. For a positive type expression E, construct:

* an erased payload majorant M_E(Z), presented by a small container when E is data-valued, with a fixed decoding `d_E`
  to the ordinary constructor tuples/function graphs stored by a value; and
* a predicate `L_E(rho, eta, w)` on its candidate payloads, or a truth predicate `L_E(rho,eta)` when E is
  proposition-valued. Here eta fixes actual earlier field values and fixed parameters. L_E is monotone in rho. Its
  satisfying decoded payloads are exactly the interpretation of E at the corresponding valuation, on well-typed eta.

M and d do not depend on the currently selected subsets R or Q. Positive *stored* data positions occur in the majorant.
Quantified witnesses used only to establish propositions occur in L, not necessarily in any stored position. The
container parameters Z describe candidate carriers, not their selected subsets. Current-family type annotations are
never stored in d. Genuine stored Type_m values range over the entire U_m at a higher grade, and can therefore include
any eventual lower-grade family code without changing M; this is distinct from attaching a complete same-grade type
annotation to each recursive node.

The construction admits only the following monotone operations on guards: conjunction, disjunction, existential
quantification over a fixed candidate/ambient set, universal quantification over a fixed domain, recursive membership
tests, and least fixed points of systems built from these operations. A quantifier's domain must not grow with rho.
Restricting an existential witness to a selected type is written `exists x in M_A. L_A(rho,x) and ...`. Universal
function-field conditions similarly quantify over a fixed domain and test the positive codomain guard. A recursive or
positive-dependent type in a Pi domain is rejected, so this construction never rewrites a relation-dependent universal
domain as an implication with a negative membership antecedent.

The elementary clauses are explicit:

1. **Fixed data and proof-free constants.** For an interpreted type A not containing a varying positive slot, M_A is its
   ordinary extension and L_A is membership in it, independent of rho. Its classifier and field bound give a set in the
   relevant V_n. Fixed propositions supply their ordinary truth value. Type_m as an actual stored field uses U_m and
   classifier succ(m). Annotation domains use their fixed finite/otherwise bounded semantic carriers.
2. **A recursive slot.** At indices i, a Type-family slot has candidate carrier Z_j and guard R_j(i,w); its majorant is
   one recursive position. A Prop-family slot has singleton proof payload and guard Q_j(i). Recursive parameter tuples
   are fixed by uniformity. No index labels or proof derivation trees are inserted in data payloads.
3. **A dependent Pi.** Its domain A is fixed with respect to the varying slots. If each codomain E(a) has majorant
   shapes S_a and positions P_(a,s), the data majorant has shapes `product a:A. S_a` and positions `sum a:A.
   P_(a,s(a))`. Decode it as a graph f. Its guard is `forall a in A. L_E(rho,eta[a],f(a))`. A proposition-valued Pi is
   the same fixed-domain universal condition, with singleton proof payload. Both guard clauses are monotone.
   Products/sums over a small A preserve the grade bound. A universe domain costs succ(m), never m.
4. **A proof field, including existential predicates.** Replace its stored payload by the canonical proof element
   regardless of the guard. Retain the truth lifting of its proposition in L. For example `Nonempty(E)` is `exists x in
   M_E. L_E(rho,x)` and has no stored position for x. Proof witnesses may instead range over the larger ambient domain
   in a Prop declaration; they still are not stored in low Type nodes. Their domains are fixed candidate sets, so
   growing rho can only make more witnesses satisfy the guard.
5. **A dependent field telescope.** For an erased candidate prefix f_1,...,f_(k-1), the next field has its fixed
   candidate majorant and predicate L_k(rho,prefix,f_k). Retain ordinary field values; replace proof fields by the
   canonical element. The telescope predicate is the finite conjunction of the guards in telescope order, along with
   externally checked type/index side conditions. The possible majorant shapes form the appropriate dependent sum over
   the previous shape values, not an independent product. The domain-stability lemma in B explains which dependencies
   are allowed and why these candidate shapes do not change with rho. Hence the conjunction is monotone at each fixed
   candidate tuple. Ill-typed candidate prefixes need not denote source terms; majorant decoding exists for them, and
   their membership guard is false. Guards are defined structurally on candidate schemas rather than by trying to run a
   source program with a false proof assumption.
6. **Constructor choices.** The majorant is the finite sum of its telescope majorants, with tags and field tuples as
   decoding. Its guard is the appropriate telescope guard and constructor result-index constraint. A proposition
   constructor contributes an existential guard over its entire candidate field telescope. Its witnesses are independent
   of the data positions of any surrounding proof field.

### B. Domain stability from the actual typed occurrence check

The needed lemma is narrower than parametricity of all source programs: in a field type accepted as positive, varying
selected subsets of a positive slot can affect positive memberships and proof guards, but cannot change a fixed data
domain/shape operation or observe the nominal code of that slot. Prove it simultaneously with A, over the evaluated
Value cases and the preceding-field context. The proof uses the fact that all implicit type arguments have been
elaborated, provisional current-block constructors are unavailable, and only the cases below can consume a dependent
local. It does not assert that `doesNotOccur`'s bare Var case examines its type.

* **VSort and annotations:** fixed grades/kinds/scopes are constructor-checked; a certified positive parameter is
  forbidden in the declared sort. A sort-valued variable is a fixed Type/Prop argument. If a field itself stores an
  arbitrary universe value, its candidate domain is the whole smaller U_m at grade >= succ(m), not a rho-selected
  recursive carrier. Ordinary family data cannot be used as a sort: its declared family type is not a universe former.
  The disjoint semantic tags validate the conversion rule that prevents this; no propositional cast can bypass
  positivity without presenting its equality/proposition in an inspected non-positive argument.
* **Rigid Var:** variables from fixed parameters and block-free preceding fields have fixed candidate values at eta. A
  variable standing for a prior recursive family value is a payload, not itself a Type code. It cannot itself stand as a
  field type. A legitimate stored/provided type-valued field is treated separately: a value T:Type_m is a candidate in
  U_m, and its ordinary field bound requires succ(m)<=n; its whole universe of codes is therefore small at grade n. If
  it is passed to a polymorphic operation, the elaborated operation also receives the type containing the recursive
  slot; its argument position is examined in the VApp/family cases below. A variable standing for a preceding proof is
  the same canonical element whenever the prefix guard holds. Using that proof cannot select different domain values by
  choosing a different witness. A prior function local is also checked at its own binder: if it consumes
  recursive/positive data, its Pi domain is negative and the binder is rejected; if it returns such data, application
  yields ordinary recursive payloads, not universe codes. If it returns actual Type_m codes, their successor grade is
  charged and its complete graph is a candidate/parameter value on the allowed fixed domains. Lower-grade codes
  legitimately selected from a stored candidate prefix need not be declared syntactically impossible; the universal
  majorant described next bounds all of them. Thus a Var leaf cannot hide a legal rho-dependent arbitrary
  domain-changing operation through an unchecked function type.
* **VPi:** freshen the telescope and apply the induction at every candidate argument. Every domain is checked
  `doesNotOccur`; the codomain is checked positive. A following domain depending on a positive earlier binder is also a
  domain of this same Pi and therefore checked, not only the initial domain. Proof domains whose truth depends on rho
  are negative as domains and rejected. Fixed lifetime domains are unchanged under valuations at this point. These facts
  give exactly A3's fixed-domain premise.
* **InductiveFamilyValue:** direct current-block applications become slots and must keep the common parameter prefix and
  nonrecursive index expressions. Earlier-family applications use only final certified positive *parameter* slots; all
  true indices and nonpositive parameters are checked `doesNotOccur`. The capability test places true-index types and
  the declared sort in forbidden positions, while common parameter types are checked positively. Dependent
  common-argument admissibility is therefore a typed-prefix guard: in telescope order each supplied candidate argument
  must satisfy the positive membership lifting of its type instantiated at the preceding arguments. Conjoin those guards
  with the family application's existing guard; their fixed candidate domains and positive type checks make the
  conjunction monotone. Common parameter types are not assumed occurrence-free. A prior recursive payload cannot become
  a fixed domain by being a hidden dependent index: its elaborated family/type parameter exposing the recursive type is
  either forbidden, or is genuinely a certified positive slot and is handled as a majorant/lifting instead of as a
  constant domain. This is the operation that prevents assuming arbitrary parameterized axioms are covariant.
* **Generic VApp:** all arguments must be occurrence-free, even when the result type is traversed positively. A head
  that is not the distinguished higher-order positive slot must be occurrence-free too. Thus passing a recursive family
  code to an opaque polymorphic function, or an equality predicate inspecting that code, is rejected. If an
  occurrence-free application reduces transparently to an actual positive family or Pi, use that reduced case. A
  positive higher-order head applied to occurrence-free arguments is interpreted pointwise by C; its result is not
  treated as an opaque constant. Evaluated argument *types* are not inferred from untyped payload equality.
* **VLam:** inspectLambda supplies rigid arguments at occurrence-free domains and evaluates the body to a recursively
  positive result. Use the body induction at each actual argument. Native/recursive inspection cycles are rejected.
  Captures and the resulting typed body cannot turn an opaque occurrence into a positive shape operation.
* **NeutralThunk:** an unresolved current-block field computation is refused by the uniform-application traversal, and
  closure scanning conservatively detects block names in code/captures. For parameter capabilities, synDeps scanning
  rejects unresolved capture dependence on the candidate positive slot. A permitted independent neutral is constant with
  respect to rho and uses the fixed-expression clause. Reduction to a concrete value merely chooses another already
  covered case.
* **VProof, packed values, constructors and opaque constants:** proof interiors are erased; their propositions are
  checked occurrence-free when they occur as argument values. Packed values inspect their type and have the usual
  decoded scalar/list value. Constructors cannot turn ordinary recursive data into universe codes; they are data
  introductions with fully checked telescopes. No current-block constructor/eliminator is available to inspect a new
  recursive payload during declaration. Earlier-family selectors/matches reduce on fixed candidate values, or expose the
  explicit family/type parameter in their typed application; nonpositive dependence is then caught in the
  application/thunk cases. An independent axiom is constant, while an axiom applied to the varying type code is the
  forbidden generic-application case.

A useful separate bound handles legitimate type-valued prefix dependencies. If T:Type_m is stored or supplied in a
grade-n field telescope, succ(m)<=n. All such T lie in the fixed small U_m, and every value of El(T) lies in the fixed
V_m; both U_m and V_m belong to V_n. Thus one can use U_m and V_m as relation-independent superdomains, rather than
assume a selected lower-grade code never varies between different candidate tuples. For a fixed tuple eta its selected
code T is fixed; a dependent domain is filtered by the ordinary condition x in El(T). Dependent function shapes use that
fixed subdomain; the shape family ranges over the fixed small set U_m of possible codes. The guard quantifies over the
same selected subdomain at that tuple. Regularity bounds all these code/domain choices together since U_m is itself
small at n. The filter is independent of rho at each fixed eta. If a code is computed through an operation using the
varying current type code itself, its typed occurrence must instead pass one of the positive clauses; an opaque
inspection or relation-dependent Pi domain remains rejected, because the universal size bound alone would not prove
monotonicity. Type_n does not have this fallback as a stored grade-n field: its classifier is n+1. This avoids a
stronger-than-needed syntactic impossibility claim while preserving both the payload bound and the monotone guard
premise.

The preceding-field dependency closure is used as follows: if field k is syntactically dependent on field j and j's type
mentions the current block, k is positivity/uniformity checked even if k's surface term never names a block family.
Repeat this along its transitive dependencies. At the Var leaves, carry the context classification just given; at each
consuming application its complete elaborated argument list supplies the relevant type occurrence. Dependence on earlier
*fixed* data remains genuine dependence of the shape family on the chosen data. If an earlier positive payload
legitimately supplies a lower-universe code T, a loose majorant independently chooses a code from the fixed U_m and uses
its small domain; the membership guard equates that choice with the code read from the fixed decoded prefix. Such extra
shape choices are erased by decoding when they are only typing information. This is a positive-payload dependency with a
uniform bound, and the equality/filter is independent of rho at each fixed tuple. Other dependence on earlier positive
payloads can enter positive membership/guard tests; it cannot be arbitrarily evaluated to create an unbounded or
rho-selected negative domain. Earlier proofs contribute availability guards, not witness-selecting data. These
statements establish A5's fixed candidate telescope and positive guard clauses by induction, rather than by assuming
independent field domains or by treating every syntactically absent block name as semantic independence.

In particular, arbitrary dependent endofunctors are outside this lemma. A proposed strengthening that allowed opaque
functions to inspect a recursive type code, allowed recursive Pi domains, or omitted elaborated type arguments would
invalidate this proof. The current check explicitly rejects those consuming forms. The proof's premises are typed
occurrence rules; absence of a discovered contradictory program is not one of them.

### C. Certified positive slots, higher order and guarded composition

An earlier certified-positive family G carries the pair of invariants (M_G,L_G), not an exact container interpretation.
Its fixed nonpositive argument values and true-index domains are independent of the varying slot. Common argument types
may depend positively on earlier common arguments; validate the supplied candidate tuple in telescope order with the
existing typed-prefix/positive guard clause, rather than treating every common argument type as forbidden. For each
positive slot expression E_a, supply its majorant and its membership lifting.

Compose the *majorants* by ordinary small-container composition: an outer shape and one inner shape at every stored
outer position determine a composite shape; the composite positions are the dependent sum of inner positions. Decode
them into exactly G's stored tuples and graphs, with proof fields canonical. Positive slots used only inside proof
premises need not contribute any stored position. To compose the *guards*, interpret every membership test for slot a by
`L_Ea`, and interpret independent existential witnesses over that slot using its full candidate majorant plus L_Ea.
Intersect the resulting conditions with G's own telescope/result constraints. Since the constituent predicates are
monotone and quantifier domains fixed, guard substitution is monotone. There is no substitution of actual guarded
extensions into an ordinary polynomial formula.

If G is recursive, its previously established lifting is a least fixed point of its own guarded rules. More explicitly,
let T_(rho) be its monotone operator on relations over its fixed majorants. Guard composition gives `rho <= rho' implies
T_rho(S) <= T_rho'(S')` whenever S <= S'. The transfinite bottom iteration then gives `lfp T_rho <= lfp T_rho'`. This
supplies the monotone G lifting needed in the outer block. Mutual prior families use the same product order. Its
unguarded erased skeleton may use ordinary nested W/container closure for a bound, but its actual extension remains this
guarded relation. This argument handles Type and Prop slots together: a Prop slot supplies a truth lifting, not an
ordinary Type-valued polynomial.

For the Nonempty example, M_G is the single decoded value `mk(*)` with zero stored recursive positions and
`L_G(rho,mk(*)) = exists x in Z_A. R_A(x)`. Nesting `T | con(g:G(T))` therefore has one candidate node `con(mk(*))`; its
rule is enabled only if some T candidate is already related. Its least relation is empty without a seed. With a seed,
con is added after seed and has no hidden stored T child. This both retains proof erasure and preserves the least proof
guard. General independent witnesses use this same clause, not a stored-position surrogate.

Higher-order slots are indexed families of these pairs. For F:A->Type or A->Prop, with A fixed, the varying relation is
pointwise in a. An accepted type-level lambda is evaluated on rigid a, its domains are independent, and its positive
body supplies M_(F(a)), L_(F(a)). Dependent sums/products over A preserve the majorant bounds; guard formulas quantify
over the same fixed A. Multiple dependent binders repeat the clause in telescope order. Under any source substitution
sigma and valuation eta, the body denotation and its majorant/lifting at a agree with those of the substituted body at
the pulled-back valuation, by the syntax induction in B. Thus higher-order substitution preserves both invariants
pointwise. An arbitrary opaque function Type->Type lacks this positive-slot derivation and is never licensed by its
function type alone.

### D. Joint majorants and their explicit rank bound

For each distinct data grade n, construct the proof-erased skeleton of data families at grades <= n that can occur in a
grade-n stored payload. Ignore all proof availability guards and index consistency constraints when forming this bound.
Keep ordinary data domains/constructor fields and ordinary stored function graphs. A Type-valued sibling above n cannot
be stored through a direct field, Pi codomain or nested data container by the ordinary field-grade bound. A higher-grade
occurrence inside Prop contributes a guard only. Hence the low skeleton never obtains high Prop witness payloads.

Within a mutual block, use its final stable common positive capability set in B/C. The declared signatures yield a
*simultaneous syntactic system* of erased positive majorants and guarded membership equations. Same-block references are
variables of that system, not previously proved functors. The finite descending capability computation ensures every
retained capability satisfies the elementary positive clauses in every family, including common parameter types, and the
forbidden true-index-type/result-index/sort positions. Eliminating the equations of the unguarded majorant system by
nested ordinary least fixed points yields small shape/position containers; this closure applies to the bound alone. It
is not a claim that proof-guarded actual families are containers. Higher-order parameters are pointwise variables in the
same system. Stable capability metadata thus supports simultaneous construction and composition, without assuming a
separately completed sibling's semantic lifting in order to construct another.

At fixed p these erased majorants yield small shape/position sets S_n, B_n(s). True indices do not become stored
positions or shape domains over all possible indices. Constructor fields may choose indices, but actual result-index
labels are computed externally from bounded candidate fields. An index of type Type_n is one argument code; it does not
create a stored field ranging over U_n. Such a field has classifier n+1 and would fail the field bound. Fixed
lower-universe code fields are allowed and use the small full U_m at the higher grade.

Choose an infinite mu < kappa_n bounding the cardinalities/transitive closures of S_n and every B_n(s); regularity
bounds them uniformly over S_n. Choose a regular lambda with mu < lambda < kappa_n and nu < kappa_n bounding mu and
lambda. Put theta = 2^nu < kappa_n, so theta^mu=theta. Form the ordinary W stages

`W_0=empty; W_(alpha+1)={(s,f) | s in S_n, f:B_n(s)->W_alpha}; W_delta=union_(alpha<delta)W_alpha`.

For alpha<=lambda each stage has size<=theta. Every position set has size<lambda, so a function into W_lambda has its
range in one earlier stage; W_lambda is signature-closed. Its well-founded subset is the least unguarded W carrier.
Node/graph encoding contributes finite rank overhead per stage. The fixed constants have bounded rank and
lambda<kappa_n, hence the whole W_n has bounded rank below kappa_n and lies in V_n. Nested ordinary majorant
constructions use the same small dependent sum/product/W operations.

Define decoder d_n by W recursion: expand constructor/nested shapes into their tags and ordinary field tuples, apply d_n
at stored recursive positions, and produce actual function graphs at function fields; insert only canonical elements at
proof fields. This recursion is independent of R/Q and never inserts complete current-family type annotations or erased
parameter tuples. The image `D_n={d_n(w) | w in W_n}` is also in V_n. Its cardinality is bounded by W_n and its ranks by
the fixed decoding operations and W recursion below kappa_n. d_n need not be injective. The actual relation below is on
decoded payloads and typing, so different encodings with equal decoded fields do not acquire different semantic
membership. Packed data uses the same decoded tuples. This explicitly relates the mathematical W bound to the
representation used by Eq and conversion.

### E. Actual indexed fibers and monotone joint guards

In the ambient set define one product lattice whose components are typed relations `R_j(i,v)` on each complete
admissible index telescope and its own fixed D_(n_j), and Prop truth predicates Q_j(i). At fixed p a constructor rule
ranges over its candidate field telescope; apply its composed guard in telescope order, then compute the constructor's
result index from the actual decoded fields. Type rules add the decoded tagged field tuple v to R_j(result-index,v);
Prop rules add Q_j(result-index) when some candidate witnesses satisfy the telescope. A proof field contributes only its
truth lifting and canonical payload, even when that lifting quantifies independent high witnesses.

All quantified candidate domains are fixed. B supplies domain stability; C supplies monotone earlier-family/higher-order
liftings. Every premise is positive, so enlarging R/Q can only enable the same fixed candidate tuple or add witnesses;
it cannot retract a membership or change the payload produced by that tuple. Therefore the joint rule operator is
monotone. Take its least fixed point from bottom in the ambient complete lattice. No part of this step identifies the
selected relation with W's unguarded initial algebra. The W's only role is its grade bound and well-founded stored
payloads. Cyclic proof-only enabling conditions produce no elements without a seed, as the G example requires.

Each actual Type extension is the fiber `{v in D_(n_j) | R_j(i,v)}` and thus belongs to V_(n_j) by subset/powerset
closure. Prop extensions are truth values with one proof element. A high Prop witness can enable a low constructor, but
it enters a guard quantified in the ambient relation; it never enters the low stored tuple. This proves each family's
own bound in a mixed-grade/mixed-Prop/Type block. Complete family type codes are assembled only after the fibers are
obtained. Nominal labels contain each small instance argument tuple, not the global family relation.

Constructors enter their fibers by the defining rules. Data elimination evaluates the selected constructor branch on
decoded fields, and recursive evaluation follows only the well-founded stored W positions. Erased proof guards supply no
data descent or hidden witness extraction. The kernel's termination rules do not grant descent through proof structure.
Small Prop elimination is erased; allowed large Prop elimination is justified by the dependent uniqueness argument
below. This gives the available match/recursive computation equations even when a positive membership guard has an
independent witness absent from the W positions.

Semantic equality remains typed. Equal decoded values may inhabit different types; their untyped equality does not
assert equality of those types. Constructor injectivity/refutation is used only at a common type (or at its justified
dependent index transport). N1 starts with equality of full type codes, which provides the full dependent argument tuple
and therefore the successive type agreement of its components. No erased annotation is recovered from arbitrary untyped
payload equality.

### F. Dependent recovery and substitution

A true singleton Prop fiber has a constructor witness tuple in the least rule model. Its recovery metadata makes every
data field a whole result argument. At fixed p,i, compare two witnesses in telescope order: the source forces the first
data field; equality of preceding data fields makes the next instantiated type equal by substitution, and its source
forces the next field; proof fields have the canonical semantic element at the now-identical proposition. Induction
gives identical dependent tuples modulo proof irrelevance. A permitted data branch is independent of erased witness
choice. This is uniqueness of recoverable fields at an exact fiber, not injectivity of the Prop family's truth value. A
missing operational constructor-result conversion can leave evaluation blocked, while the actually true fiber still
supplies the semantic result-index witness. Empty large elimination needs a mathematically empty fiber, not an unchecked
unifier verdict.

State substitution at the two-invariant level before using fixed-point uniqueness: for every checked expression E,
substitution sigma and valuation eta, its fixed candidate schema/decoding and its guard formula agree with those for
E[sigma] at the pulled-back valuation. Constant cases use the previous environment's substitution lemma; Var uses its
substituted fixed candidate value; application uses the complete argument list; Pi/lambda use identical instantiated
domain valuations and the body induction; earlier-family application uses componentwise equality of composed
majorants/guards; proof fields use the same instantiated truth formula and canonical element; telescope clauses extend
the identical decoded prefix one field at a time. Every independent existential or universal is then over the same
candidate domain with the same predicate. Annotation valuations and uniform p also agree. Pointwise higher-order guards
agree at each argument, as in C.

Consequently the simultaneous constructor operators, including their independent proof-witness clauses, are equal after
this reindexing. Their bottom iterations agree at every ordinal and therefore their least fixed points agree. The
resulting fibers and completed nominal type codes commute with substitution. This proves the dependent transport needed
by N1 and the recovery argument without source Pi injectivity or an assumption that least fixed points alone imply
naturality. Noncumulative separate Prop makes proof/data classification substitution-stable. Large level polymorphism is
interpreted by first instantiating its metatheoretic valuation schema; no first-class universe of all grades is
introduced.

### G. Scope of the argument

Ordinary small-container/W closure bounds the unguarded majorants; the positive guard construction and the complete
typed occurrence case analysis above are separate Raccoon obligations. The container literature is not a theorem that
the actual guarded extensions are polynomial. In particular it cannot replace A4/C's existential witness clauses. The
accepted Nonempty example is modeled without a new language restriction.

This is an informal written relative-consistency construction for the stated calculus and an audited consistent prelude.
Its proof premises are the explicit typed positivity/declaration rules; absence of a contradiction discovered in testing
is not evidence for them. A future mechanical fundamental lemma would have to formalize these derivations and the match
equations. The construction does not establish operational canonicity, resource preservation, lifetime confinement, all
trusted-prelude obligations or every implementation shortcut. The two-Long ValueKey equal-hash shortcut is a
pre-existing implementation gap outside the repair; no collision-free hashing axiom is added. Constructor exclusions
now require local refutations checked by the ordinary typechecker, using a conservative constructor-hypothesis
schema and private checked proof helpers. The N1–N3 premise factory instantiates the principles justified here; its
eligibility checks and signatures, the hypothesis schema, conversion and unchanged branch substitutions remain
implementation obligations. This model does not verify those components or constitute an independent kernel proof.
See [checked constructor exclusion](kernel.md#checked-constructor-exclusion).
