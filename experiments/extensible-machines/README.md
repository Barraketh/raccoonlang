# Extensible machine experiment

Status: **checked language-design experiment**, 2026-10-02.

One generic command representation and lowerer work for two independently defined machines: register
allocation and a buffer protocol with changing generations and two reader permissions. An allocator issues
fresh lexical identities through a linear cursor. An abstract worker interface supports different client
implementations. A checked equality connects the buffer program to the entire CUDA body generated by the
existing `encoding.Core` API.

This supplies ordinary core ingredients for the [proposed source interface](SURFACE.md), with eager construction
of retained syntax. It does not establish that the interface replaces Core, preserves its complete guarantees,
or makes all its proofs easier. It also does not demonstrate a need for a native machine judgement, full typing
reflection, a change to implicits, or a change to evaluation. The experiment adds
one read-only Core syntax accessor and improves conservative constructor exclusion in the proof checker.

## What this adds to the earlier experiments

| Question | Checked result | Boundary |
|---|---|---|
| Can libraries define different machines without adding cases to a common machine interpreter? | `Machine` is generic in state, operation and specification; both `Pipeline` and `RegisterMachine` reuse it | Control syntax is still the fixed sequence/branch/loop fragment |
| Can allocation give two identical shapes distinct identities? | A linear cursor advances its storage index and introduces a fresh lexical scope; successive indices differ for every starting index | Allocation happens during eager generation; no runtime allocator or reclamation model |
| Can a loop change its state indices? | A universally certified body advances generation `g` to `g + 1`; generic induction establishes `g + count` | Payloads and two reader permissions are modeled; asynchronous hardware completion is not |
| Can clients use unknown workers? | `Client.construct` checks with a neutral worker parameter; a separate `CustomWorker` adds a read and proves the same progress interface | The physical pilot has two buffers and one CTA |
| Is framing tied to fixed slots? | `World.frameRun` proves a safe computation on an arbitrary identifier leaves any unequal peer exactly unchanged | This is a functional cell model, not a hardware aliasing theorem |
| Does a certificate describe actual Core output? | `Bridge.productionMatches` proves equality of the complete production kernel body and the certified lowering | Primitive hardware meanings and target-shell interpretation remain assumptions |
| Can the redundant footprint proof be derived? | Improved exclusion allows `Footprints.fromMeaning`; `Gpu.Local` no longer stores a second footprint certificate | The first experiment's separate direct backlink limitation remains reproducible |

The [first experiment](../state-machines/README.md) checked histories and backlinks. The
[second](../compositional-machines/README.md) checked abstract callbacks, framing and runtime control in a
closed model. This experiment tests machine-family extension, generative identity, indexed loop progress,
and an inspection boundary for the existing GPU library.

## Generic commands and proof obligations

[`Machine.rac`](Machine.rac) defines:

```text
Spec(S, Op) = step + emit
Code(Op) = skip | atom | seq | branch | loop
Meaning(spec, code, run) : Prop
Cmd(spec, P, Q) = code + run + Meaning proof + Safe(run, P, Q) proof
```

`Safe` quantifies over every modeled runtime and state. Its result predicate is false on a fault. Sequence
requires a matching intermediate predicate, branches establish a common result, and a fixed-invariant loop
preserves its invariant for every count. These proofs use unknown semantic functions and predicates.

The lowerer is generic in the machine specification. Only an atom invokes `Spec.emit`; the sequence, branch
and loop cases never inspect a pipeline operation or register state. Its `Emits` relation threads a fresh-symbol
counter and binds a runtime loop index. A `Lowered` result carries the block, next symbol and a checked witness
that they came from the given tree and emitter.

The specification's emitter is not automatically a refinement of its step function. A dishonest specification
could describe a safe abstract step and emit an unrelated instruction. The admitted target claim is correspondence
to the declared emitter; a hardware refinement theorem must connect each emitter to the modeled step. The
experiment's negative tests detect mismatches against the chosen specification, not dishonesty in arbitrary
new specifications.

[`RegisterMachine.rac`](RegisterMachine.rac) supplies its own states and operations and uses the current
`Registers.fits` budget predicate and existing Core emission templates. A real pool/split/join construction checks
alongside the model. `Demo.registers` and `Demo.registerLowering` use the same generic command and lowering rules
as the buffer machine. This is not a universal contract for the existing register library.

## Fresh allocation and framing

[`Allocation.rac`](Allocation.rac) seals a linear `Cursor(root, next)` and scoped references indexed by root,
allocation identity, storage identifier and width. Allocating consumes the cursor, creates a fresh allocation
lifetime, declares the storage, and returns the successor cursor through a callback. Two equal-width allocations
therefore have different storage identifiers and different lexical identities.

`Allocation.successorDisjoint(n)` proves `n != n + 1` for arbitrary `n`. Scopes enforce nominal lifetime identity;
there is no proposition comparing `Lifetime` values as ordinary data. The rejection fixtures check cursor
duplication, forged cursor/reference constructors, wrong root and allocation identity, and an escaping reference.

[`World.rac`](World.rac) models a collection of cells as `Nat -> State`. Updating one identifier preserves every
unequal peer. `frameRun` uses any supplied safety contract to exclude faults and preserve the peer; it does not
need to inspect the computation. `Demo.cycleFramesPeer` applies it to the actual pipeline cycle for arbitrary
identifiers and generations. `Demo.genericAllocationFrame` combines framing with the successor-disjointness proof.

The allocation and framing families are general, but the physical shell binds exactly two buffers and their
two private accumulators. More allocations need a general shell/binding environment. Arbitrary CUDA runtime
allocation, overlapping views, identifier reuse and dynamically changing footprints are untested.

## Generations and reader permissions

[`Pipeline.rac`](Pipeline.rac) tracks a phase, two active-reader bits, a generation, a stored value and an
accumulated payload. A cycle stores `iteration + 1`, publishes, opens both reader permissions, reads through each,
closes both, then recycles. Recycling requires both readers closed and increments the generation. A read
preserves generation and adds the stored value to the payload modulo `2^32`.

Primitive commands have both phase-only and precise generation contracts. [`Source.rac`](Source.rac) adds
allocation- and loan-scoped `Reader` and `Borrowed` values. `Source.cycleAt(buffer, g)` goes from empty generation
`g` to empty generation `g + 1`. `Source.cycleSyntax` proves that its code is the same tree for every generation.
Reusing a command or reader at a stale generation fails checking.

[`Progress.rac`](Progress.rac) states the indexed loop obligation:

```text
Advances(run, I) = forall g, Safe(run, I(g), I(g + 1))
repeat: Advances(run, I) -> I(g, initial)
     -> Post(I(g + runtime.count), repeat(run, runtime, initial))
```

The induction is over the runtime count. The retained body is constructed once; a representative generation
does not determine its syntax. `Demo.everyCount` specializes the generic theorem to the two-buffer program,
establishing empty buffers at generation `runtime.count` from generation zero. It quantifies over the runtime
input, rather than checking a selection of iteration counts.

`Demo.three` additionally evaluates three iterations: each buffer ends at generation 3, stored value 3 and
payload 12. The pilot's output expression sums both payloads, giving modeled value 24. This is an abstract
evaluation result; no GPU numerical result is claimed.

## Open worker implementations

[`Client.rac`](Client.rac) checks with this abstract worker interface:

```text
forall root allocation id,
  Ref(root, allocation, id, 64) -> Body(root, allocation, id)
```

A body provides its certified command and a generation-advance theorem. The client allocates two buffers,
calls the worker on each, combines their independent state interpretations, and derives progress without
examining the worker's implementation.

The public `Source.certify` accepts a correctly indexed reference, a command and its progress proof.
[`CustomWorker.rac`](CustomWorker.rac) uses this route to supply three reads per generation, rather than the
standard two. Neither the machine definition nor the client nor the lowerer changes. Its `everyCount` theorem
establishes the same generation result, and its three-iteration evaluation has payload 18 per buffer.

The convenient scoped interface remains sealed. Explicit certification can construct additional descriptions
when their contracts check. Descriptions and erased proofs are unrestricted; copying them does not establish
that a physical resource currently satisfies their input contract. The current Core API still supplies linear
tile authority and enforces the concrete generator's use of it.

## The production Core connection

[`CorePilot.rac`](CorePilot.rac) uses the existing `Core.tiledKernel`, `shared`, `storeMine`, `sync1`, `reads`,
`sread`, `reg`, `get`, `set`, `loop`, `release` and `gstore` operations. It allocates two arrays of 64 unsigned
values, uses one 64-thread CTA and a runtime loop bound `K`, and accumulates two reads from each array per iteration.
Publication and recycling each emit a barrier for each buffer.

The two logical reader permissions correspond to two sequential read sites within one native `Core.reads`
scope. They do not represent independently executing GPU roles or asynchronous DMA completion. The shared
values are uniform, and reads use an index reduced modulo 64. The target interpretation also assumes that runtime
`K` is a valid unsigned count and that the launch and global output storage satisfy the existing Core contract.

The production change is `Core.kernelSyntax(p)`, a read-only accessor. The `Program` constructor stays sealed;
inspection cannot replace its code or launch metadata. `Core.render` still requires `Core.WellFormed(p)`.

[`Bridge.rac`](Bridge.rac) lowers both certified worker trees, constructs their declarations, accumulators,
runtime loop and guarded output store, and checks:

```text
Eq(Cuda.Block,
   Core.kernelSyntax(CorePilot.program).body,
   Bridge.compile(Bridge.plan).body)
```

This equality includes every statement in the body: storage declarations, symbol bindings, loads, accumulator
snapshots, both buffers' barriers, loop bound and output. It is an ordinary checked equality over evaluated AST
data. It is not reflection of the Raccoon generator's typing derivation, and it does not prove the lowering of
every possible Core client. Kernel metadata comes from `Core.tiledKernel`; the equality concerns the body.

[`Render.rac`](Render.rac) renders the actual Core program. The retained [`generated.cu`](generated.cu) is that
output. This develops the checked-AST/program-artifact options in `REGISTERS.md` §9 and avoids a proof import
cycle. It does not implement mutual minting across sealed modules or prevent the general Cuda renderer from
printing uncertified kernels.

## Indexed elimination improvement

The earlier `derived_footprint` proof failed because the exclusion checker tried to quote every constructor-index
equation. A computed function index has no ordinary quotation in that context, so it abandoned the certificate
before using a data-index constructor clash.

`RefinementCertificates` now permits a refutation to use the quotable subset of index equations. This weakens
its hypotheses; it does not change which refutations the ordinary checker accepts. The final certificate is
still checked, and quotation failures never authorize an exclusion. Tests cover successful data-index exclusion
and retention of an inhabited constructor when only an unsupported function equation is available, including
deliberately wrong pruning proposals. The existing adversarial suite continues to pass.

The earlier experiment now derives `Owns` from `Meaning` using structural induction. Its redundant stored
footprint field has been removed, and the former expected-rejection fixture now checks a generic derivation.
The first experiment's direct `RegisterProtocol.Step` backlink still has its original conservative `MissingCase`;
this change does not resolve every indexed-elimination limitation.

## Validation and remaining work

Run from the repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 experiments/extensible-machines/run.py
```

Set `RACCOON` to the CLI command or prepare the classpath with `sbt graalvmNativeImageClasspath`.
The shared runner verifies each module and expected diagnostic at its intended local definition, regenerates
CUDA, checks its loop/barrier/allocation shape, and runs host C++ syntax checking when `clang++` is available.

Result: **37/37 checks, with 14 accepted modules and 23 rejected counterexamples.** Rejections cover stale or
incorrect generations, recycling with an active reader, double close, missing publication, wrong resource identifiers,
wrong machine/resource/lifetime, forged introductions, wrong semantics, and changed target AST or bindings.
The separate custom worker's all-count proof and payload evaluation are accepted checks.

The first experiment passes 69 checks. The compositional experiment passes 34 checks, now 14 acceptances and
20 rejections. `sbt -batch validate` passes all 930 tests, including two new refinement tests. `gpu/check.sh`
passes its 189 reported checks with the CUDA toolkit enabled. The new generated CUDA also compiles through
`nvcc`/`ptxas` for `sm_100a`: 26 registers,
512 bytes shared memory, zero stack frame and zero spill loads/stores. No hardware execution was performed.

The result is about model contracts, scope/identity restrictions, and target correspondence. It does not establish
hardware race freedom, deadlock freedom, fairness, asynchronous completion, a general memory model, or coverage
of arbitrary accepted effects in the existing GPU library. Those require additional semantics and operation
contracts. The proposed surface syntax has not been implemented.

The [real-client comparison](../machine-core/README.md) starts with an independent alternative library and a
port of TinyGEMM, then records missing functionality for A3b attention and persistent pair GEMM. Those comparisons,
with Core's full guarantee set as the baseline, are needed before choosing a general source interface or
committing to a native machine judgement.
