# Attention A3a: two query tiles in ping-pong

Status: built (2026-10-01), not run on hardware: the score buffer in `Core.rac`, `examples/attention_pingpong.rac`,
`harness/attention_pingpong_test.cu`, `rejected/attention_pingpong_mutants.py`; `NOTES.md` §"A3a" records what was
awkward. §6 lists where the build departs from the design as first written. It is the first performance step of
`gpu/ATTENTION.md` §6 A3, on the core of `gpu/encoding/`. It assumes A2 (masks, tails, bf16 output) and the readability refactor (no `…Done` tokens,
chunk combinators, shared roles). Facts about FA4 are from `ATTENTION.md` §2.7 (Dao-AILab `flash-attention`,
`flash_attn/cute/flash_fwd_sm100.py` at `616b0e8`).

## 1. Why

A1 overlaps only `S_{j+1}` with the softmax of block `j`, and the exponentials never overlap a `PV` product
(`ATTENTION.md` §2.1). FA4 gets its overlap from two query tiles per CTA:
- while one softmax warpgroup computes block `i`'s probabilities for its tile, the tensor cores run the other tile's
  products;
- the MMA thread serves the tiles in turn: as soon as one tile's probabilities are published, it issues that tile's
  `PV_{i−1}` and `S_i`, then waits for the other tile's.

A3a takes that schedule and nothing else from A3's list. No correction warpgroup, no rescale threshold, no polynomial
exponential, no `setmaxnreg`, not persistent. Those are A3b and later, each measured against the previous step. A3a
alone is not expected to match FA4, so it does not by itself meet the bar for hardware runs. What it settles is the
protocol shape every later step builds on.

## 2. The schedule

**The CTA.** Two 128-row query tiles, `Q0` and `Q1`, and 384 threads in 12 warps:

| Warps | Role |
|---|---|
| 0–3 | softmax for tile 0, an aligned warpgroup, one row per thread |
| 4–7 | softmax for tile 1, an aligned warpgroup |
| 8 | MMA (one elected thread) |
| 9 | load (one elected thread) |
| 10–11 | idle (where A3b's correction warpgroup goes, with 8–11 in FA4's layout) |

The grid is `(ceil(seq / 256), BH)`. Every role runs one block count, `n = ceil(seq / 128)`, or for a causal kernel
`min(ceil(seq / 128), 2·blockIdx.x + 2)`, tile 1's. So in a causal kernel tile 0 runs one more block than its rows
need, whose keys all lie past them: its mask makes their `p` 0 and `α` 1.

**Tensor memory**, all 512 columns, one 256-column region per tile (`splitTmem`), each a score buffer (§3):

| Columns | Region |
|---|---|
| 0–127 | `S0`, tile 0's scores; `P0`, its probabilities, overlays columns 64–127 |
| 128–255 | `Ô0` |
| 256–383 | `S1`, `P1` likewise |
| 384–511 | `Ô1` |

**Shared memory:**
- `Q0` and `Q1` stages (32 KB each), each loaded once and held;
- a K ring and a V ring of 2 stages each (64 KB each), as A1's.

**The MMA order** (FA4, `flash_fwd_sm100.py` 1851–1990). Per key block `i`:
1. **Before the loop:** `S0_0 = Q0·K_0ᵀ`, commit to `S0` full; `S1_0 = Q1·K_0ᵀ`, commit to `S1` full. Release `K_0`.
   The loop then runs `n − 1` times.
2. **For `1 ≤ i < n`:** await the stage `V_{i−1}`, then for each tile `t` in turn, 0 then 1:
   1. await `Pt_{i−1}`;
   2. issue `Ôt (+)= Pt_{i−1}·V_{i−1}`; after tile 1's, release `V_{i−1}`;
   3. for tile 0, await the stage `K_i`;
   4. issue `St_i = Qt·K_iᵀ` and commit to `St` full.

   Then release `K_i`.

   `St_i` writes St's columns, which `PVt_{i−1}` just read as Pt. PTX orders an MMA's tensor-memory A reads before a
   later MMA's D writes from the same thread (the pipelined pair "A reads → D writes", A33), so no barrier is needed.
   A commit covers every earlier `tcgen05` operation of the thread. So `St` full's phase `i` also covers `PVt_{i−1}`,
   and a warpgroup that observes it has both new scores and a quiescent `Ôt`.
3. **After the loop:** await `V_{n−1}`; for each tile in turn, await `Pt_{n−1}`, issue `PVt_{n−1}` and commit to `St`
   full, now meaning "final"; release `V_{n−1}`.

Every product accumulates. The one after the loop is the first when `n = 1` and not otherwise, and code after a loop
is generated once, so no product can know from its type whether it is the first. Instead Ô starts at 0: in block 0
the warpgroup's rescale writes zeros, which is `α · Ô` for `α = 2^−∞ = 0` and an Ô that starts at 0.

**Why tile by tile.** A tile's next scores wait only for its own probabilities. While warpgroup 0 computes block `i`'s
probabilities, the tensor cores run tile 1's `PV1_{i−1}` and `S1_i`, and the reverse; the two warpgroups stay half a
period apart. An order that awaited both tiles' P before issuing either tile's products would hold tile 0's `S0_i`
until warpgroup 1 finished, and the two warpgroups would run in step, with nothing to overlap their exponentials.
FA4 also has a barrier that makes the two softmax warpgroups take turns (`s0_s1_barrier`), but it is off
(`flash_fwd_sm100.py` 254); A3a has none.

**Two rings, not FA4's one.** The MMA thread holds `V_{i−1}` from tile 0's `PV0_{i−1}` to tile 1's `PV1_{i−1}`,
and `K_i` from tile 0's `S0_i` to tile 1's `S1_i`, so it holds a V stage and a K stage at once. FA4 keeps them in one
ring, `K_0, V_0, K_1, V_1, …`, whose consumer holds two stages. The stage ring's consumer holds one stage at a time
(`await` takes its `ConsumerAt`, and `releaseByMma` gives it back). With two rings each consumer still holds one: the
K ring's from `S0_i` to `S1_i`, the V ring's from `PV0_{i−1}` to `PV1_{i−1}`. The shared memory is the same, and the
loader's lead is the same, two blocks of each, because the loader alternates K and V anyway. One ring would need a
consumer that holds a window of stages, which A3a does not need.

**The softmax warpgroup for tile `t`**, block `i`:
1. Await `St_i` and fence `after_thread_sync`.
2. **One pass over S, the row in registers.** Load all 16 chunks (128 f32 values) into registers and `wait::ld`;
   compute the maximum, `p`, and the sum from the registers. This is A3's "one pass over S" item, and it is required
   by the overlay: every read of `St`'s upper half must finish before the first write of `Pt` over it.
3. Write `Pt` in place over `St`'s upper half: 16 stores of 4 packed columns.
4. Rescale `Ôt`'s row by `α` (for `i ≥ 1`; in block 0, set it to 0). This must wait until `PVt_{i−1}` has completed:
   Ô is read and written while the tensor cores accumulate into it. Step 1's wait already covers it: the commit that
   completed `St_i` followed `PVt_{i−1}` (the MMA order above).
5. Publish: `__syncwarp`, `wait::st`, `fence::before_thread_sync`, arrive on `Pt` full (128).
6. Update `m` and `l`.

**The epilogue:** as A1/A2 per tile (`storeO`), after the tile's last product.

## 3. Protocols

The existing protocols cover most of A3a:
- **The Q stages:** two one-stage rings, each held across the loop (`holdStage`).
- **The K and V rings:** A1's, whose consumer holds each stage across both tiles' MMAs (`holdStage`) and releases it
  by `releaseByMma` after the second (K after `S1_i`, V after `PV1_{i−1}`).

**What is new: the overlaid score buffer.** One token family per tile replaces A1's separate S ring and P
exchange. The tile's region `St ∪ Ôt` is one buffer (`withScoreBuffer`), passed between the MMA thread and the
warpgroup. The block index is not in the types; each side's phase register counts the blocks at run time.

| State | Held by | Means |
|---|---|---|
| `RowsAt(o)` | warpgroup, between blocks | the buffer is the MMA thread's; `o` says whether Ô is defined |
| `Scored(o)` | warpgroup, after awaiting `St` full | `St` holds block `i`'s scores, visible; `Ôt` quiescent (the product of `i−1` complete) |
| `Read(o)` | warpgroup, after the one-pass load and `wait::ld` (`loadRow`) | the row's scores are in registers; S's columns may be overwritten |
| `Probs(o)` | warpgroup, after writing all of `Pt` (`writeProbs`) | `Pt` written, pending `wait::st`; then, after `rescaleRow`, `Probs(held)` |
| `Final` | warpgroup, after awaiting the last commit (`awaitFinal`) | `Ôt` complete and visible; no MMA in flight on the region |
| `MmaAt` | MMA thread, between blocks | the buffer is the warpgroup's |
| `Published` | MMA thread, after awaiting `Pt` full | `Pt` and the rescaled `Ôt` visible to the tensor cores |
| `Issued` | MMA thread, from `takeMma` and after `PVt_i` | its work on the buffer issued, uncommitted; S's columns free for `St_{i+1}` |

What the overlay changes from A1:
- **Loading and writing are separate states.** `Read` is a state between loading and writing. `Probs` can be
  entered only from `Read`, so no store to `Pt` precedes the last `wait::ld` of `St`.
- **Full and empty are one barrier pair.** "S full" and "P empty" become one: the commit after `St_{i+1}` (issued
  after `PVt_i`, by the pipelined-pair rule) is what the warpgroup next waits on. When it completes, both `PVt_i` and
  `St_{i+1}` are done, so the warpgroup gets the new scores and a quiescent `Ôt` together. That is FA4's
  `P_full_O_rescaled` barrier and its S-full barrier.
- **The last iteration.** There is no `St_n`, so the final commit follows only `PVt_{n−1}`. The warpgroup's last
  state is `Final`, from which only the epilogue proceeds; the MMA thread's side ends at `MmaAt` (`finishMma`, which
  emits nothing, since `awaitFinal` waits for that commit).
- **One coverage state.** `writeProbs` writes all 16 chunks of `Pt` from a `Row`, which has 16 chunks, so `Probs`
  needs no chunk index (M14 holds by construction, as for A1's `writeP`).
- **Ô defined before the first product.** `publishProbs` takes `Probs(held)`, which in block 0 only `rescaleRow`'s
  zeroing makes.

**Barriers per tile.** `St` full (count 1, the MMA thread's commit) and `Pt` full (count 128, the warpgroup's
arrivals). One phase of each per block. Every wait means the current phase or the one before it (P3), by the round
argument of `docs/SEPARATION_PILOT.md` §4.

**Pieces** (`docs/SEPARATION_PILOT.md`). The region `St ∪ Ôt` is one exclusive piece that moves from the tensor
cores (`Issued`) to the warpgroup (`Scored`, `Read`, `Probs`) to the tensor cores (`Published`) and back, through
the two barriers. While the warpgroup holds it, it holds all of it. While the tensor cores hold it, the warpgroup
holds nothing of it.

## 4. Obligations and new assumptions

**Assumptions:**
- **A33 (pipelined pair, A reads → D writes)** becomes load-bearing. Without it, `St_{i+1}` would need its own wait
  on `PVt_i`'s commit. A hardware probe should test it: an MMA reading P from tensor memory, then an MMA writing the
  same columns, from one thread with no barrier between.
- **A39 (new):** an MMA that reads its A operand from tensor-memory columns overlapping its own D region is not used.
  The overlay keeps P (A of `PVt`) and `Ôt` (D of `PVt`) disjoint; only `St_{i+1}` (D) overlaps `Pt` (A of the
  previous MMA).

**Register pressure:** 128 f32 scores per thread plus statistics. FA4's softmax runs at 192 registers with
`setmaxnreg`. Without it (A3a), 384 threads at the default share must fit: 65536 / 384 = 170 registers per thread.
That is a risk to measure (`-Xptxas -v` on hardware, or `cuobjdump`), not to assume. As built, the row's 128 loaded
values die as their masked scores are made (pass 1 keeps the 128 masked scores, not the loads), and each chunk's 8
exponentials die at its 4 packed stores, so the peak is the 128 masked scores plus about 30 (statistics, the 8
exponentials and 4 packed words of one chunk, addresses and the chunk's key index). The generated code declares every
value `const` or as an `asm` output, so the allocation is ptxas's.

## 5. Plan

Items 1–4 are built (§6); 6 waits.

1. **Core.**
   - The overlaid buffer: a family, its operations, and `withScoreBuffer(tile)` over a 256-column region.
   - A one-pass `loadRow` producing 16 `F32x8`, and `writePChunks` over `Read`.
   - A 384-thread kernel builder.
2. **Example:** `examples/attention_pingpong.rac` (non-causal and causal, f32 and bf16 as A2), sharing the softmax
   arithmetic with A2's roles where it can.
3. **Harness:** A2's harness parameterized over the launcher.
4. **Mutants:**
   - a write to `Pt` before the one-pass load completes;
   - the rescale before `Scored`;
   - `St_{i+1}` issued before `PVt_i`;
   - the epilogue before `Final`;
   - a tile's warpgroup touching the other tile's region.
5. **Hostile review**, especially of the overlay (§3) and A33's use.
6. **Hardware**, when A3b, the correction warpgroup and the exponential split, is expected to reach FA4's
   `cta_group::1` time.

## 6. As built

Where the build departs from the design above as first written (2026-10-01):
- **Tensor-memory layout.** Each tile's S, P and Ô are one 256-column region (§2's table), not FA4's S0, S1, Ô0, Ô1:
  `splitTmem` gives each tile's score buffer its region, and a buffer's operations address only it.
- **Ô starts at 0** (§2, after the MMA order). The first product does not overwrite; the warpgroup's block-0 rescale
  zeroes Ô. A2's `mmaPV` reads `OState` instead; here the product after the loop cannot.
- **States** (§3's table): `Probs` has no chunk index; the warpgroup rescales after writing P, as A2 does; `Issued` is
  also the MMA side's first state.
- **Causal block count** (§2): one count per CTA, tile 1's.
- **Masks once per block.** Pass 1 (`mapRow`) keeps the masked scores in registers for pass 2 (`writeProbs`), so
  each chunk is masked once per block, not twice as in A2.
